# Short, searchable title (name the platform or stack when specific)

**Status:** Verified | Hypothesis | Needs recheck  
**Area:** topic or project area  
**Platform:** hardware/device and execution platform, or explicitly Platform-independent / Unknown  
**Stack:** OS, runtime, libraries, or tools relevant to this learning; Unknown if not established  
**Context:** originating project or task, plus the situation where this note is useful  
**Applies to:** affected component/API and exact versions or commit links when known; state unknown versions  
**Validation:** what was checked and where (hardware, simulator, host, or source review); state important untested paths  
**Last checked:** YYYY-MM-DD and scope of that check; Unknown if not recorded

Keep these labels and their order. Choose one status. Do not infer a tested platform from a related project or mistake a simulator result for a hardware result. Keep unknowns explicit. An edit to wording or metadata is not a fresh technical validation.

## Symptom or context

What happened, or what situation makes this useful? Include only details needed to reproduce or recognize it.

## Cause or hypothesis

What explains the behavior? Mark an unconfirmed explanation as a hypothesis.

## Fix or lesson

What worked, what failed, or what should be tried first? Keep this specific and actionable.

## Verification and evidence

How was the result checked? Link public issues, documentation, commits, or other evidence where useful. If not verified, say what remains unknown.

Use accessible, pinned source links where possible. Distinguish reproduced results, source review, and earlier reported results. If evidence is missing or stale, use Needs recheck and say what would resolve it.
